Root cause: production decisions run prompt v1 of the credit decision prompt, and its template has no place for policy updates. The code retrieves the 12 Oct EV-grant bulletin correctly, but the decision model never sees it. It only gets the old handbook rule, "the amount financed is the purchase price". On top of that, the €6,000 the grant check finds is never subtracted: the affordability check gets the full price. The process went wrong right after the grant check. I didn't change anything.

Where it diverged
Steps 1–3 are correct in both traces. Policy retrieval and the grant check apply the new policy properly.
Step 4 is the first wrong step. The €6,000 isn't carried forward. The affordability check gets the list price instead of the price after the grant.
Step 5 repeats the mistake. Prompt v1's template only includes the application and the handbook. The bulletin is passed to the prompt (it's in the trace metadata) but never appears in the message the model receives. So the model applies the old handbook rule, as instructed.
Why the control looks fine: it went through exactly the same broken steps. It's correct only because a plug-in hybrid gets no grant, so leaving the grant out changes nothing. The controls show the fault only affects grant-eligible cars. They don't show that the pipeline handles the new policy.
How widespread
All 32 disputed traces show the same pattern: the grant check returns €6,000, but the affordability check gets the full list price. In the cases I spot-checked, the price after the grant falls within the credit line (one is exactly equal), so each one should have been approved.
Every decision in the last 30 days used v1: 120 in total across disputed, control, untagged and staging traffic. Prompt v2, which adds the policy updates to the template, has never run.
Not confirmed

The traces don't show whether the app code or the model chose the amount sent to the affordability check. There's no recorded model call for that step. So switching production to v2 would fix the decision prompt but may not fix step 4. That step should be checked in the code.
